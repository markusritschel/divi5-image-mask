# Image Mask for Divi 5

WordPress plugin (`divi5-image-mask`, prefix `d5im_`, text domain `divi5-image-mask`) that adds an "Image Mask" group (German „Bildmaske“) to the Design tab of Divi 5's Image module: the image is clipped (CSS `mask-*`) to one of Divi's background mask shapes or to an uploaded SVG/PNG. Modelled on Divi's **Background > Mask** settings (shape picker, transform buttons, aspect ratio, size, position, offsets), without its colour and blend mode, which mean nothing for a clip. Follows the builder-filter pattern of `../divi5-woocommerce-additions`. UI texts are English with a German translation in `languages/`.

## Commands

```bash
# Test site (Docker, http://localhost:8094, admin/admin, author/author): WordPress + German core files + this plugin + Divi 5
e2e/setup.sh ~/Projekte/webdesign/Divi/Divi.zip      # Divi is licensed: it goes into the Docker volume, never the repo
cd e2e && pnpm install && CHROMIUM_PATH=/usr/bin/chromium pnpm test   # ~100 s; the Divi tests skip without Divi
docker compose -f e2e/docker-compose.yml down -v     # throw the test site away
```

LocalWP: symlink the repo into the site like the other Divi plugins:
`ln -s ~/Projekte/webdesign/Divi/divi5-image-mask ~/Webdesign/LocalSites/<site>/app/public/wp-content/plugins/divi5-image-mask`.
There is no build step: `assets/image-mask.js` is plain JavaScript.

Release ZIP and updates (same pattern as `../divi5-mobile-menu`):

```bash
composer install --no-dev          # the update checker (vendor/, gitignored); optional in a dev checkout

```

## Architecture

One PHP file (`divi5-image-mask.php`) and one builder script (`assets/image-mask.js`). The settings live in one attribute, `image.advanced.mask` (`group-items`, desktop value only), an object with `style` (`none`, a Divi mask name, or `custom`), `custom` (the uploaded image as Divi's upload field stores it: `{src, id, alt, titleText, width, height}`; only used while `style` is `custom`), `transform` (array of `flipHorizontal`, `flipVertical`, `rotate`, `invert`, as Divi's mask transform stores it), `aspectRatio`, `size`, `width`, `height`, `position`, `horizontalOffset`, `verticalOffset`, `outsideOpacity` (`"0%"`…`"100%"`), and for the zoom animation `animation` (`none`/`zoom`/`zoomOut`), `animationTrigger` (`load`/`view`), `animationDuration`, `animationDelay` (`<n>ms`), `animationEasing`, `animationDirection` (`normal`/`alternate`), `animationPlays` (`"1"`…`"10"`, unitless range), `animationLoop`, `animationReplay` (`on`/`off` toggles). Missing keys mean Divi's mask defaults (landscape, stretch, center, 0 %) and no animation (once on: load start, 500 ms, no delay, `ease`, normal, 1 play).

**Builder side** (`assets/image-mask.js`, loaded into the app window through `PackageBuildManager::register_package_build()` on `divi_visual_builder_assets_before_enqueue_scripts`, dependencies `divi-module-library` and `divi-vendor-wp-hooks`). The filters `divi.moduleLibrary.moduleAttributes.divi.image` and `divi.moduleLibrary.moduleSettings.groups.divi.image` add the attribute and the group `designImageMask` (Design tab, priority 20). Fields are Divi's own components. Mask Shape is a `divi/select` dressed as Divi's mask picker: the component `divi/select-mask` itself uses (`Qs`), with its class `et-vb-mask--select` (Divi's grid CSS) and options whose `label` is a render function `({isHovered, isSelected}) => <span class="label"/> + <img>` with Divi's thumbnail (`getMaskSvg({type: "thumbnail"})`) in Divi's colours. Own entries because `divi/select-mask` builds its options internally from Divi's mask library and takes no extra one, and adding „Custom“ to that library (filter `divi.maskAndPatternLibrary.mask`) would put a dead entry into every Background › Mask picker. The options are built in `filterComponentProps` (Divi's mask bundle loads after the first render), which must also return `className`, `displayCheckMark` and `updateMenuPositionOnLoad`: its result replaces `component.props` (with them only in `component.props`, the grid styling was lost). The sidebar renders in the top window, which has its own React (18.2.0, not the app window's): the label elements are made with `window.top.vendor.React`. „None“ stores `style: "none"`, „Custom“ `style: "custom"`. `divi/upload` (Custom Mask) shows only with `custom`. `divi/button-options` with `multipleChoices` for the transform (copied from Divi's mask field definition, which needs `onChangeParams: ["multipleChoices"]`), `divi/select` and `divi/range`. Each field's `visible({attrs})` hides what doesn't apply (transform/size without a mask, aspect ratio for a custom mask, width/height unless size is custom, position/offsets while stretched). The transform field's `filterComponentProps` receives the module's `attrs` too and offers only "Invert" while a custom mask is set (it must build the options itself: the props Divi passes in carry none). The number of plays is a unitless `divi/range` (`defaultUnit: ""`, `allowedUnits: [""]`, `cssProperty: "z-index"`, as Divi's own count fields) and stores e.g. `"3"`. German labels are short (one word where possible) because Divi title-cases labels („Seitenverhältnis Der Maske“).
Divi's mask bundle (`window.divi.maskAndPatternLibrary`) is _not_ a WordPress dependency: Divi 5.15.1 registers it with `enqueue_app_window: false` and loads it itself after the first render, so naming it as a dependency makes WordPress drop the script. The script looks it up when it builds CSS.

**Translations**. The script's texts are English and go through its own `__(text)`, which looks them up in `Divi5ImageMaskData.texts` (falls back to the English text). That global comes from `data_app_window` (`PackageBuildManager` names it after the package): `d5im_builder_texts()`, a map English → `__( …, 'divi5-image-mask' )`, translated in PHP with the site's language. So one `.mo` per language covers PHP and script, with no JSON translation files and no `wp_set_script_translations()` (untested with `PackageBuildManager`; `../divi5-flip-cards` uses `wp.i18n` without them, so its script texts can't be translated yet). Every text is spelled out in `d5im_builder_texts()` so `wp i18n make-pot` finds it; `e2e/tests/strings.mjs` fails when the script uses a text missing there or untranslated in German. `d5im_load_textdomain()` loads `languages/` on `init`. German ships as `de_DE` and an identical `de_DE_formal` („Deutsch (Sie)“ sites); other German variants (`de_AT`, `de_CH`) get English.

**Preview**. The builder renders the module in React, without the plugin's PHP. `syncPreview` (on a `MutationObserver` and a `divi.data` subscription, once per animation frame) reads `getModuleAttr(<uuid from the module's class et_pb_image_<uuid>>, 'image.advanced.mask')` for every Image module and writes one rule per masked module into `<style id="d5im-preview">` (`.et_pb_image_<uuid> .et_pb_image_wrap{…}`). A stylesheet rather than inline styles, so React re-renders can't wipe it. While Divi's mask bundle hasn't arrived, `maskCss()` returns `null` and the sync retries every 250 ms (deliberate: nothing else wakes it when the bundle loads).

**CSS** (`d5im_mask_css()` in PHP, `maskCss()` in JS, same logic, same output). A Divi shape comes from Divi's library (`MaskAndPatternUtils::get_mask_svg()` / `getMaskSvg()`, both `escape: false`), so shapes added through Divi's `divi_mask_and_pattern_library_mask` filter work too. It uses the shape's _inverted_ SVG: Divi paints its regular path _over_ the background (the „Ellipse“ is a frame with an elliptical hole), so the inverted path is where the background shows through, and the image shows there. "Invert" takes the regular SVG. Rotation picks Divi's `rotated` variant; flips are a `<g transform="matrix(…)">` around the SVG's content (viewBox sizes from `get_mask_default_viewbox_settings()`), because a CSS transform would flip the image as well. The SVG goes into `url("data:image/svg+xml,<rawurlencode / encodeURIComponent>")`. A custom mask is `url("<esc_url_raw>")` (`d5im_custom_url()` / `customOf()`: `src` of the stored object or a plain URL, and only with `style: "custom"`; reading only strings made images chosen with the picker do nothing, since the tests had stored plain URLs) and shows the image where it is opaque; inverted, it is excluded from a full `linear-gradient` layer (`mask-composite: exclude`) placed at the mask's position, so the zoom grows both layers from the same point. Size: stretch → `100% 100%` (not Divi's mask `calc(100% + 2px)`, which bleeds over seams of an overlay and would only shift a clip), cover/contain, custom → `<width> <height>` (`auto` for empty). Position: always four-value (`left|right <offset> top|bottom <offset>`, `left 50%`/`top 50%` for centre), written here rather than with Divi's `get_background_position_css()`, which turns single-word positions like `top` into `center`. `mask-repeat: no-repeat`. Outside Opacity (`d5im_outside_alpha()` / `outsideAlpha()`, rounded to two decimals) adds a translucent full layer `linear-gradient(rgb(0 0 0/<alpha>) 0 0)` at the _top_ of the layer list, composited with `add`: on top so an inverted custom mask cuts its hole first (`add,exclude`) and the hole then gets the faint layer too. The zoom animation's start sizes are one per layer, with this layer at `100% 100%`, so only the shape zooms. Lengths are checked against a pattern (number with px, %, em, rem, vw, vh), anything else falls back to the default.

**Animation** (`d5im_animation_css()` / `animationCss()`). Both animations are one keyframe, `@keyframes d5im-zoom{from{mask-size:var(--d5im-start)}}`: without a `to`, it runs to the element's own `mask-size`, so it works for every mask and scales around the mask position. `--d5im-start` is `0 0` for „Zoom In“ (applies to every layer, so an inverted custom mask starts fully closed too; earlier, keeping its full layer at 100 % showed the whole image at the start) and `calc(<each layer's size> * 3)` for „Zoom Out“ (layer sizes from `d5im_mask_sizes()` / `maskSizes()`, shared with the mask CSS; 3 is a chosen factor: for Divi's shapes most of the image shows at the start). A plain CSS `reverse` was deliberately not offered: the animation holds its last frame (`both`), so a reversed zoom-in ends with the image hidden. Only for stretch and custom size: CSS can't interpolate between `cover`/`contain` (keywords) or `auto` and a size, so the fields are hidden for cover/fit and an `auto` width or height just jumps. Both properties go into the inline style, `--d5im-animation` as `d5im-zoom <duration> <easing> <delay> <plays> <direction> both` (plays: `animationPlays` clamped to 1–10, `infinite` with Loop Endlessly), with the class `d5im-animate-load` or `d5im-animate-view` on the wrap. `D5IM_ANIMATION_CSS` and `D5IM_ANIMATION_JS` are printed inline once per page, right before the first animated image (`static` flag in `d5im_render_block()`), so the keyframes exist before that image is painted (an enqueued file would land in the footer: image shown, then zoomed). „Load“ runs `animation: var(--d5im-animation)` at once; „View“ only with `d5im-in-view`, which an `IntersectionObserver` adds once a fifth of the image is in the window (thresholds `[0, 0.2]`, checked as `intersectionRatio >= 0.2`: `isIntersecting` is true for any sliver, which would start a zoom on an image barely peeking in). „Replay When Scrolled Back Into View“ (a toggle, shown only with the view start) adds `d5im-repeat-view`, for which the script keeps observing and removes `d5im-in-view` once the image is completely out of view, so the mask returns to its start unseen and plays again on return; without it the script unobserves after the first start. Until then a view image's mask is held at `var(--d5im-start)` (closed for Zoom In, oversized for Zoom Out, so neither flashes), but only under `.d5im-js`, a class the inline script sets on `<html>`: without JavaScript the image just shows. Everything sits in `@media (prefers-reduced-motion:no-preference)`. Builder preview: the stylesheet carries the keyframes and per animated module `animation:` directly (as „load“, whatever the start setting); when a module's rules change, `syncPreview` restarts its animation (`cancel()` + `play()`), since a changed duration alone wouldn't.

**Page side**. `render_block` on `divi/image` reads the attribute from the block, and `WP_HTML_Tag_Processor` appends the CSS to the `style` attribute of the first `.et_pb_image_wrap`. Inline, so there is no order-class or static-CSS-cache dependency.

**SVG uploads** (`d5im_upload_mimes`). WordPress refuses SVGs (they can carry scripts). The `upload_mimes` filter allows `svg` for users with `unfiltered_html` only (administrators on a single site, super admins on multisite): they can already add any HTML, so this opens nothing new. Other roles get WordPress's „not allowed to upload this file type“.

**Updates**. `d5im_register_updater()` sets up Plugin Update Checker (`vendor/`, from Composer) against this repository's GitHub releases, taking the asset `divi5-image-mask-v<version>.zip` that the release workflow attaches; the `Update URI` header keeps wordpress.org from claiming the slug. Without `vendor/` or on any error it does nothing (deliberate: never break the site for updates). `D5IM_GITHUB_TOKEN` in `wp-config.php` authenticates while the repository is private.

**Tests** (`e2e/`, node:test + Playwright against the Docker site). `cases.mjs` lists 18 mask settings (none, shapes with every transform, custom size/position/offset, a custom SVG stored as the upload field's object and as a URL, inverted, ignored with a shape selected, Custom without an image, Outside Opacity on a shape and in an inverted custom mask's hole), each with points where the image must be visible, masked out or faint (`isFaint()`: red over white at reduced opacity); `php/mask-page.php` builds a page with one Image module per case (optionally merging more block attributes per module, and attributes for the column), all showing a solid red 400×300 PNG, and writes `uploads/d5im-circle.svg` as the custom mask. The check reads the rendered pixels from a screenshot (`colorsAt()` decodes it on a canvas: red = visible), so it tests what a visitor sees, not the CSS text. `page.mjs` runs the cases on the page, `builder.mjs` in the builder preview (same pixels), drives the sidebar (shape picker → "Arch", "Flip Horizontal" button, 30 typed into Outside Opacity, Save, then the page), picks „Custom“ in the shape list and an SVG through WordPress's real media window („+ Add Image“ → Media Library → attachment → „Upload an image“, the button Divi labels the confirm), then checks what is stored, the transform options (only Invert), the hidden aspect ratio and the preview's pixels, and that a shape hides the picker again, and, with the site language switched to `de_DE`, that every field label and the size options are German (needs WordPress's German core files, which `setup.sh` installs: WordPress refuses an uninstalled site language). It also checks the animation fields (shown for stretch, hidden for cover; Replay only with the view start; plays hidden while looping; a typed number of plays stored unitless and played that often in the preview) and that the preview restarts the zoom after a settings change. Fields are found by Divi's classes `.et-vb-field-image-advanced-mask-<sub-name>` (kebab-case: `aspect-ratio`, `animation-trigger`; a camelCase selector silently matches nothing) and `button[data-name]`, the group by its label. `animation.mjs` checks the zoom on the page through the Web Animations API (`getAnimations()`, paused and moved to start/end, then pixels): name, duration, delay and speed curve (from `animation-timing-function`: a CSS animation's effect easing is always `linear`), closed at the start and clipped right at the end (also an inverted custom mask), no animation for cover, „view“ closed until scrolled to, plays, Loop Endlessly (winning over plays), Alternate, plays clamped to 10, Replay ignored with the load start, a replaying mask closing when scrolled fully away and zooming again on return while one without Replay stays finished, Zoom Out mostly visible at the start and right at the end and held at its start size (`300% 300%`) until scrolled to, with Outside Opacity all faint at the start and only the shape zooming (also an inverted custom mask), shown without JavaScript, nothing animated with `reducedMotion: 'reduce'`, and the inline assets printed once. `strings.mjs` checks the translation files statically (wrapped `.po` entries included). `filters.mjs` checks that Divi's Design › Filters act on the masked image (`module.decoration.filters` `opacity: "50%"` → the shape faint; `blendMode: "difference"` → red turns cyan inside the shape, white outside). Divi's Blend is `mix-blend-mode` on the module's root, and `.et_pb_column` has `z-index: 2`, so it blends only with what the column paints: the test gives the column a white background (without it nothing blends, mask or not). `upload.mjs` uploads an SVG through the REST API as admin (201) and as author (refused for the file type).

## Known limitations & improvements

- **[high] Relies on Divi 5 internals** (filter names, attribute/group schema, `divi/select` with Divi's `et-vb-mask--select` class and its option label render functions, the upload field's stored object, `MaskAndPatternUtils`, `window.divi.maskAndPatternLibrary`, the lazy loading of that bundle), checked with Divi 5.15.1 only. After Divi updates, open the module's "Image Mask" group and run `pnpm test`.
- **[medium] One value for all breakpoints, no hover or sticky state.** The fields have `responsive`, `hover` and `sticky` off. Per-breakpoint masks would need a `<style>` with media queries instead of the inline style.
- **[medium] Animation assets are printed with the first animated image.** If Divi or another plugin renders that block's HTML and throws it away (e.g. for an excerpt) before the real one, the page has no keyframes: masks show, but don't zoom. Not seen with Divi 5.15.1.
- **[low] The „view“ start needs the inline script.** A Content Security Policy that blocks inline scripts leaves `d5im-js` unset: images show without zooming (the „load“ start is CSS only and keeps working).
- **[low] Zoom only for stretch and custom size**, and a custom size needs width and height; cover and fit can't be animated in CSS.
- **[medium] Option group presets untested.** The fields declare `preset: ["style"]` like Divi's overlay fields; saving the group as a preset and applying it has not been tried.
- **[low] Box shadow, border and hover overlay** sit on or inside `.et_pb_image_wrap` and are clipped with the image (a box shadow vanishes). Follows from CSS; not covered by a test.
- **[low] Custom masks can't be flipped or rotated**: a CSS mask has no transform of its own, and an SVG used as a mask image can't reference the uploaded file. Prepare the file the right way round.
- **[low] Uploaded SVGs are not sanitized.** Only `unfiltered_html` users can upload them, and the plugin only uses them as CSS mask images (never inline), but the file itself stays reachable by URL like any upload.
- **[low] SVGs in the media library** have no size metadata, so WordPress shows their thumbnails small or blank and logs `Undefined array key "width"/"height"` (`wp-admin/includes/image.php`) once per upload; the mask itself works.
- **[low] Builder texts follow the site language** (tested). Divi's builder runs on the front end, where WordPress uses the site locale; whether a user's own profile language changes them is untested.
